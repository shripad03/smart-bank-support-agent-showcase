This register lists defects and gaps that were reproduced or confirmed in the code at the baseline commit. It is the input for prioritising Phases 1 to 9. It does not propose fixes.

**Severity** is rated for a regulated financial-services deployment. **High**: must be resolved before any real customer use. **Medium**: resolve before general availability. **Low**: schedule opportunistically.

**Evidence** is either a probe, a code reference (`file:line`), or both. Rows whose behaviour could not be tested offline are marked **Unverified**. Probes ran offline (network blocked, dummy API key, temporary log directory, fake model); the application code was not modified.

**Planned phase** uses the programme roadmap: 1 Scope, 2 Architecture and security, 3 Agent quality and reliability, 4 API and frontend, 5 Persistence, 6 Observability, 7 Deployment, 8 Product and operations, 9 Optimization.

## Probe method

Offline probes were run from a temporary script outside the repository using the production modules with a scripted model. Live probes used the production `get_llm()` path against the configured provider, paced to stay under its rate limit. The retrieval probes are now a committed, repeatable baseline: `eval/baseline_retrieval.py`.
